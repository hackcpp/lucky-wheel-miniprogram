# 幸运转盘小程序 · 项目计划与设计（Plan v1.2）

> 目标：帮「选择困难症」用户随机决定今天**吃什么 / 玩什么**，用转盘把决策变成一件轻松好玩的事。
> 形态：**纯前端小程序**，零后端、零域名依赖，本地存储即可运行。
> 状态：本文档为计划与设计稿，**尚未编码**。
> 变更：v1.2 — 权重**仅影响选择概率，扇区保持等分绘制**（视觉不体现权重差异）；v1.1 权重抽奖纳入 MVP、云同步明确不做。

---

## 1. 产品定位

| 项 | 内容 |
|---|---|
| 一句话定位 | 点一下，今天吃啥玩啥交给转盘 |
| 目标用户 | 选择困难、想快速做决定、喜欢和朋友一起玩的人 |
| 核心价值 | 降低决策成本 + 一点仪式感和趣味 |
| 使用场景 | 饭点纠结、周末不知去哪、两人都不想拍板时甩锅给转盘 |
| 差异化 | 吃/玩固定预设 + 用户自建「自定义」分类、可设权重（仅影响概率）、可转发给好友一起抽 |

**为什么能纯前端**：决定"吃什么玩什么"是本地随机逻辑，不需要服务端计算；选项数据量小，用 `wx.storage` 足够。因此本版**不申请服务器、域名、微信支付、登录**，准备门槛极低——只要小程序账号 + 微信开发者工具。

## 4. 交互设计

### 4.1 转盘抽奖主流程
```
[点击「开始」]
   ↓
转盘加速 → 匀速 → 缓动减速（ease-out，约 3.5s，转 5 圈+）
   ↓
指针停在某一扇形中心
   ↓
结果卡片弹入（轻微缩放+淡入）
   ↓
[就它了] 关闭卡片  /  [再转一次] 重新旋转
```

### 4.2 关键交互细节
- **防重复点击**：旋转中禁用「开始」按钮，避免叠加动画。
- **旋转中锁定入口**：旋转动画进行中禁用「管理选项」入口（按钮置灰 + `pointer-events:none`），防止动画未结束即切入管理页导致首页转盘状态错乱；动画结束自动恢复可点。
- **切换分类**：重置转盘角度、重绘等分扇形，并清空当前结果。
- **选项为空**：转盘显示占位圆，并提示「去管理页添加选项」。
- **结果确定性**：动画结束直接返回预先**按权重随机**选中的索引，不做反向命中计算（更稳，不会"看着指A实际是B"）。
- **权重与视觉分离**：扇区始终**等分绘制**，不体现权重大小；权重仅在随机算法中提高该项被抽中的概率（机制默默生效，不向用户展示权重说明）。

### 4.3 分享
- `onShareAppMessage`：标题如「帮我决定今天吃什么！」，路径带分类参数 `?cat=eat`。
- `onShareTimeline`（朋友圈）：配图用转盘截图或首图。

## 5. 视觉设计（简约清新）

### 5.1 配色方案
| 用途 | 色值 | 说明 |
|---|---|---|
| 页面背景 | `linear-gradient(165deg,#f0faf4 → #e6f4ec)` | 极淡绿单色系渐变，呼应转盘绿 family（one-palette 纪律） |
| 主色 / 开始按钮 | `#07c160` | 微信绿，亲和、有"确定"感 |
| 转盘扇区配色（单色系明度梯度） | 设计值为 `hsl(150, 46%, 92%→60%)`，实现时通过 `hslToHex` 转为 hex 后赋给 canvas `fillStyle` | 单一绿 family（与全页主色同 hue），低饱和（<80%），明度浅→深梯度；相邻明度差恒定可见、首尾差最大，扇区可区分且奇数不撞色。符合 Anti-Slop 配色纪律：one palette / max 1 accent。**注意：小程序真机 canvas 2d 不支持 `hsl()` 字符串，直接填会解析错乱** |
| 指针 | `#0a8f4f` | 深绿（同 family），与全页主色一致，不再引入第二色相 |
| 主文字 | `#333333` | 深灰，对比清晰 |
| 次要文字 | `#999999` | 辅助说明 |
| 卡片背景 | `#ffffff` | 纯白浮层 |

### 5.2 字体与间距（基于 750rpx 设计稿）
- 标题：36rpx / 字重 600
- 正文：28rpx
- 辅助：24rpx
- 圆角按钮：48rpx（胶囊形）
- 卡片圆角：24rpx
- 区块间距：32rpx

### 5.3 核心组件视觉
- **分段控制器（分类 Tab）**：顶部胶囊，选中态填充主色，未选中透明描边。
- **转盘**：正圆，顶部一个朝下的小三角指针（固定在 12 点）；中心一个圆形「开始」按钮（主色，白字）。**扇区等分，不按权重变形**。
- **结果卡片**：屏幕居中白色圆角卡，大字号显示抽中项，并展示其权重（如「权重 ×3，更易被抽中」），下方两个操作按钮。
- **权重标识（管理页）**：列表每项名称旁显示权重标签（如「×3」），新增时提供 1–5 选择器。

### 5.4 动效原则
- 旋转用 `ease-out cubic`，自然减速。
- 结果卡片 `scale 0.9→1` + `opacity 0→1`，约 250ms。
- 尊重系统"减弱动态效果"设置（可选，V2 做）。

## 6. 技术架构

### 6.1 总体
- **渲染层**：默认 WebView 即可；后续可迁移 **Skyline** 提升动画流畅度（canvas 2d 在 Skyline 下同样支持）。
- **语言**：WXML / WXSS / JS（ES6）。
- **状态**：页面级 `data` + 全局 `app.globalData`；选项持久化走 `wx.storage`。
- **无网络**：本版所有逻辑本地完成，不需 `wx.request`，因此**无需配置合法域名白名单**。

### 6.2 模块划分
| 模块 | 路径 | 职责 |
|---|---|---|
| 转盘组件 | `components/wheel/` | canvas 绘制等分扇形+文字、旋转动画、触发 `result` 事件 |
| 首页 | `pages/index/` | 组装分类 Tab + 转盘 + 结果卡片 + 分享 |
| 管理页 | `pages/manage/` | 分类切换、选项增删改 + 权重设置、持久化 |
| 存储工具 | `utils/storage.js` | 分类选项的读写、初始化 |
| 预设数据 | `utils/presets.js` | 内置吃/玩分类与候选项（含默认权重） |

### 6.3 数据模型
```js
// 存于 wx.storage，key = 'wheel_categories'
{
  eat:  { name: '吃什么', items: [{ text:'火锅', weight:1 }, { text:'烧烤', weight:2 }, /* ... */] },
  play: { name: '玩什么', items: [{ text:'看电影', weight:1 }, /* ... */] },
  custom: { name: '自定义', items: [{ text:'下楼走走', weight:1 }, { text:'刷会视频', weight:1 }, /* 用户自建，与吃/玩并列 */] }
}
```
- `items` 每项为**对象** `{ text: 显示名, weight: 权重 }`；`weight` 为正整数，默认 1，范围建议 1–5。`weight` **只参与随机概率计算，不改变转盘扇区大小**（扇区始终等分绘制）。
- `custom`（自定义）为**用户自建的独立分类**，与 `eat` / `play` 并列存储，不自动合并；初始给几个中性默认项（如「下楼走走 / 刷会视频」），用户可在管理页随意增删改。
- 「吃什么 / 玩什么」保持固定预设，仅「自定义」完全由用户决定内容。
- **本地存储版本兼容（重要）**：读取时**以当前版本预设结构为基准**，用存储值逐分类覆盖；若旧版本数据缺某个分类（如早期无 `custom`），须用默认结构补齐，不能因为直接 `JSON.parse` 旧数据导致新分类为 `undefined`、访问 `.items` 抛错（原型曾因此出现「点击自定义转盘不刷新」）。建议为存储结构预留 `version` 字段，升级时按版本做字段补齐/迁移。

### 6.4 转盘算法（核心，务必设计清楚）
坐标系：canvas 标准角，0 在 3 点方向，顺时针为正；**指针固定在 12 点方向 = `-π/2`**。

1. **扇形划分（等分）**：选项数 `n`，每片夹角 `seg = 2π / n`。第 `i` 片占据相对角度 `[i·seg, (i+1)·seg)`，叠加当前旋转角 `rotation` 得实际绘制角。→ **扇区始终等分，视觉不体现权重**。
   - **扇区配色**：单一绿 family 的明度梯度（`H=150, S=46%`，明度按项数从 92% 均分到 60%），相邻明度差恒定可见、**首尾明度差最大**故奇数也不撞色；全页锁定一个绿 family（指针改用深绿 `#0a8f4f`、权重标签改主绿），满足 Anti-Slop「one palette / max 1 accent」纪律。可为组件封装 `wheelSectorColors(n)` 取色。
   - **canvas 颜色格式（坑）**：微信小程序真机 canvas 2d 对 `hsl()` 颜色字符串支持不全，解析后会出现红/紫/蓝等杂乱色（如火锅扇区变成灰紫色）。实现时**必须先把 HSL 转成 hex 或 rgb** 再赋给 `fillStyle`；浏览器原型亦同步用 hex，保证三端一致。
2. **随机选中（按权重）**：设第 `i` 项权重 `w_i`，总权重 `W = Σw_i`；`r = random()·W`，从头遍历累积权重，命中 `r` 落入的片即为 `targetIndex`（权重越高越易中，但扇区大小不变）。
3. **目标旋转角**（让第 `targetIndex` 片中心对齐指针）：
   - 第 `i` 片中心相对角 = `i·seg + seg/2`
   - 需要：`rotation + 该片中心相对角 ≡ -π/2 (mod 2π)`
   - 解得基准目标角，再叠加 `5` 个整圈（`5·2π`）保证"多转几圈"的视觉。
   - 归一化到大于当前 `rotation`，确保始终向前转。
4. **动画**：
   - 时长 `duration ≈ 3500ms`。
   - 缓动 `eased = 1 - (1 - t)³`（ease-out cubic）。
   - 每帧 `rotation = startRot + (desired - startRot)·eased`，调用 canvas 重绘。
   - 用 `canvas.requestAnimationFrame`（节点方法，非全局）驱动，避免每帧 `setData`（性能关键）。
5. **结果**：动画结束直接 `triggerEvent('result', { index: targetIndex, value })`，与视觉停的位置严格一致。

> 注意：绘制文字时若选项名过长（>5 字），需截断或缩小字号，防止扇形溢出。扇区等分后不再有"权重导致窄扇区"问题；`weight` 上限（如 5）仅为控制概率极端化、避免某项几乎不可能被抽中。

## 9. 风险与注意点

| 风险 | 影响 | 应对 |
|---|---|---|
| canvas 2d 需异步取节点 | 首屏可能空白一瞬 | `ready` 生命周期内用 `SelectorQuery` 取 node，取到再绘制 |
| canvas 颜色格式 | 真机扇区颜色错乱（红/紫/蓝等） | 设计可用 HSL，但 canvas 绘制前必须转 hex/rgb；浏览器原型也统一用 hex |
| 选项过多（>12） | 扇形过窄、文字挤 | 限制单类上限（如 16），或提示精简 |
| 视觉与概率不一致 | 等分扇区下权重高者扇区并不"更大"，用户可能误以为等概率 | 机制不向用户解释；权重仅在管理页设置时可见（×N 标签），不做结果/首页提示 |
| 每帧 setData | 卡顿 | 动画只在 canvas 内重绘，不跨线程 setData |
| 类别状态不同步 | 首页 `cur` 与管理页 `cur2` 各自维护，进管理页默认 eat，导致「首页选玩什么、管理页却显示吃什么」的错位 | 进/出管理页双向同步 `cur↔cur2` 并高亮对应 Tab；返回时重置转盘角度 `rotation=-π/2` 后重绘 |
| 文字过长 | 溢出扇形 | 超过字数截断 + 省略号 |
| 审核 | 本版纯本地、无隐私接口 | 过审容易；若后续加登录/支付再补隐私声明 |
| 游客模式限制 | touristappid 不能真机预览/上传 | 正式提审前替换为自己 AppID |

### 11.5 时间线
- 注册 + 拿 AppID：**当天**
- 审核：普通 **1–3 个工作日**（最长 7 天）
- 过审即点即发布，无需等待

### 11.6 填写项参考（注册与发布时直接选用）

#### A. 注册前需准备的材料（个人主体）
| 填写项 | 说明 | 参考 / 要求 |
|---|---|---|
| 邮箱 | 未绑定过微信公众平台（公众号/小程序/开放平台任一） | 用长期可用的常用邮箱（如 `you@example.com`） |
| 管理员微信号 | 主体本人、已实名 | 能扫码、能收验证码的微信 |
| 主体姓名 + 身份证号 | 个人实名认证 | 须与管理员微信实名信息一致 |
| 手机号 | 接收审核 / 安全通知 | 管理员本人手机号 |

#### B. 小程序资料填写参考（后台「设置 → 基本设置」）
| 填写项 | 要求 | 参考项（任选其一，可改） |
|---|---|---|
| 小程序名称 | 4–30 字符，一年仅改 2 次 | ① 幸运转盘　② 今天吃啥　③ 决定帮　④ 转盘一下　⑤ 选啥好 |
| 小程序简称 | 可选，列表/分享展示用 | 转盘 / 幸运转盘 |
| 简介 | ≤120 字 | 「纠结今天吃什么玩什么？转一下，把选择交给运气。」<br>「帮选择困难星人随机决定吃什么、玩什么，好玩又解压。」 |
| 服务类目 | 必选，个人需可注册 | `工具 → 工具`（最贴合）；若该类目受限，退选 `生活服务` 下的合适子类目 |
| 标签 | 可选，利于搜索曝光 | 随机选择 / 决策助手 / 吃什么 / 玩什么 / 转盘 / 休闲 |
| 小程序头像 | 144×144px，png/jpg | 建议：简约清新风，一个**彩色转盘 + 指针**图标；主色微信绿 `#07c160` 或暖红指针 `#ff6b6b` |

> **名称避坑**：不要含"官方/旗舰/第一"等绝对化用语，不要蹭知名 IP；个人主体名称不能与已存在的公众号/小程序重名，提交前在后台先查重。

#### C. 类目选择参考路径
1. 后台「设置 → 基本设置 → 服务类目 → 添加类目」。
2. 推荐：`工具` 类目（最贴合"随机决策工具"定位）。
3. 若 `工具` 类目对个人主体受限，改选 `生活服务` 下合适子类目（以后台类目树实时显示为准）。
4. **类目选错是拒审高频原因**，提交前确认该类目个人主体可注册、且无需额外资质。

#### D. 发布时上传的代码包
- 在微信开发者工具点「上传」，填**版本号**（如 `1.0.0`）与**项目备注**（如「首版：吃/玩/自定义转盘 + 权重」），再到后台「版本管理」提交审核。
